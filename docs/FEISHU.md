# 飞书多维表格对接

V1 只把“用户确认后的四项预约信息”写入飞书，导师分配、联系和接待状态全部由人工在飞书完成。不要把完整聊天记录写入飞书。

## 建表

创建一个多维表格和一张业务表，例如“免费真人预约”，至少包含以下字段：

| 字段 | 建议类型 | 来源 |
| --- | --- | --- |
| 预约编号 | 文本 | 系统生成，作为幂等编号 |
| 昵称 | 文本 | H5 |
| 微信 / 联系方式 | 文本 | H5 |
| 当前困扰描述 | 多行文本 | H5 最终确认文本 |
| 希望获得什么帮助 | 多行文本 | H5 |
| 提交时间 | 文本 | 服务端 ISO 时间 |
| 处理状态 | 单选或文本 | 初始为“待分配”，人工更新 |
| 分配导师 | 文本 | 人工填写 |
| 接待结果、最近跟进时间、备注 | 多行文本 | 人工填写 |

字段名必须与代码中的名称一致，或同步修改 `server/feishu.ts` 的 `fieldsFor` 与状态映射。

## 环境变量

复制 `.env.example` 为 `.env.local`，填写 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_TOKEN`、`FEISHU_TABLE_ID`。App Secret 只保存在服务端。

给飞书应用开通并发布创建记录、查询记录所需权限。具体权限以当前飞书开放平台页面显示为准，不要把 App Secret 提交到 Git。

## 真实验收

1. 启动 API 后调用 `/api/health`，确认 `feishuConfigured: true`。
2. 从 H5 真实提交一条预约，确认返回 `recordId`，并在飞书中看到一条新记录。
3. 用同一个预约编号重试，确认不会新增第二条记录。
4. 在飞书人工填写“处理状态”和“分配导师”，刷新结果页确认状态查询能读到更新。
