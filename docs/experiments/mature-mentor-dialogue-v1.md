# 成熟导师式自然对话实验 V1

## 范围与结论

本实验只调整普通聊天的语言规则，并新增一个隔离多轮评测脚本。没有修改安全、专业转介、Issue、预约、隐私、Fallback 或模型调用次数。

结论为 **可供人工体验，暂不建议合并或发布**。实验版在倾诉留白、现实建议、真人拒绝后的继续聊天和专业边界上有改善；但“用户纠正理解后不得同轮追问”仍不稳定，关系场景也仍会出现模式化分析。

## 机制审计摘要

- 聊天 Prompt 由 `system-prompt.md`、`conversation-rules.md`、`naturalness-rules.md`、Issue、路由、安全和测评规则拼接而成。原先系统 Prompt 与自然表达规则都重复规定了提问、长度和共情，容易让模型同时执行多种目标。
- 正常 `/api/chat` 会把当前 Issue 的消息传给模型；`worker/handler.ts` 只保留当前 Issue 上下文，用户上下文上限为 18,000 字符。安全、Issue、交接和事实仍由服务端基线控制。
- 模型输出普通自然文本时，诊断会记录 `MODEL_SUCCESS` 与 `MODEL_PARSE_FAILED`，随后由 `naturalReply()` 通过兼容路径返回；这不是 Fallback。模型空白、截断或被安全/交接校验拒绝时才会进入 `fallbackReply()`。
- `fallbackReply()` 仍保留固定的安全、交接、实用建议和倾诉兜底。这次没有改变它；实验版 18 个最终响应均未使用 Fallback，旧版有 1 次。

## 改动

1. 将人设改为成熟、亲切、有判断的成长支持伙伴，删除“知心大姐姐”等不稳定角色化表述。
2. 将自然表达规则从多版叠加改为四组短规则：跟住眼前事实、成熟但不端着、提问与帮助有分寸、避免套路和重复。
3. 将两条不能靠语气推断的要求上提为明确输出边界：
   - 用户只想倾诉，或 `ask_question=false` 时，本轮只用陈述句留白。
   - 用户纠正理解时，不补写时间、动机、关系历史或心理原因；安全例外外不追加问题。
4. 新增 `npm run eval:mentor`。它在两个隔离代码副本中走完整 `worker/handler.ts` 聊天链路，比较最终回复、控制诊断、Fallback、耗时和 DeepSeek Token；结果文件由调用者传入私有路径，不会写入仓库。

## 真实多轮 A/B（完全虚构）

基线为 main `aa63244249a17deb72a1f0f3964baa2a114bd30d`；实验版为本分支。每个场景两轮，共 18 个最终响应/版本。即时安全场景由既有安全门禁直接回答，因此不调用模型。

| 场景 | 人工对比 | 实验版判断 |
| --- | --- | --- |
| MM-01 新城市孤独、只想倾诉 | 旧版首轮追问影响，实验版首轮也会询问影响；第二轮实验版改为两句具体承接并留白。 | 改善，但首轮仍偏导诊。 |
| MM-02 三项目挤压、明确要办法 | 实验版用“谁在等、卡在哪、让老板定优先级”回答，较旧版更像现实工作判断。 | 通过。 |
| MM-03 被打断后纠正 AI | 两版在纠正后都再次追问影响；实验版虽承认“不往自信上扯”，仍未遵守同轮停止追问。 | 不通过。 |
| MM-04 冲突后失联的关系判断 | 实验版第二轮更直接回应“值不值得”，但首轮出现“典型模式”“成人依恋测评”等不必要分析。 | 混合，不能算稳定改善。 |
| MM-05 给父母汇款的边界 | 实验版区分了支持意愿与可持续上限，并提供可直接使用的“三千是我能长期给的”表达。 | 通过；结尾仍多问了一句。 |
| MM-06 回县城照顾母亲 | 实验版把照护期限、工作含金量、县城生活和可逆选项拆开，判断有帮助；但篇幅偏长。 | 通过，需人工体验确认长度。 |
| MM-07 真人入口后又拒绝预约 | 旧版被校验替换为固定倾诉 Fallback；实验版自然允许继续聊天，未使用 Fallback。 | 通过。 |
| MM-08 即时安全演练 | 两版均由既有安全门禁返回相同安全确认，未调用模型。 | 保持。 |
| MM-09 用药与减量 | 实验版明确“不建议自己减”“让开药医生判断”，更简洁且专业边界清楚。 | 通过。 |

## 继续前的判断

如果要把这版推进到产品级验证，下一步不应继续堆叠语言示例。应先由产品负责人决定：

1. 是否将“纠正后本轮不得追问”升级为窄范围的服务端回复校验；仅靠 Prompt 目前不稳定。
2. 是否允许关系场景使用“模式”“依恋测评”等术语；若不允许，应作为明确的表达禁区，而不是继续增加人设描述。
3. 是否接受重大选择场景的长回答；若不接受，需要产品定义“详尽但不冗长”的可观察长度标准。
