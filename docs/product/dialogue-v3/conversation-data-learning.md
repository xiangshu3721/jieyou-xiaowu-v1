# C04｜对话数据训练、评测与持续进化模块 v0.1

> STATUS: DESIGN_DRAFT / DATASET_NOT_BUILT / TRAINING_NOT_RUN / PRODUCTION_NOT_CHANGED
> 目标不是“自动喂数据给 DeepSeek”，而是建立可追溯、可控、可合法使用的数据驱动质量提升机制。

## 1. 什么叫“训练”：区分四个层级

| 层级 | 真实含义 | 初期优先级 | 边界 |
| --- | --- | --- | --- |
| T0 场景评测 | 用真实感场景检验现有行为，并建立长期回归库 | P0 | 不需改模型权重 |
| T1 示范学习 | 将高质量导师回复与反例整理为少量受控示例/评审标准，校准 Prompt 与策略 | P0 | 不自动把完整案例塞入每轮 Prompt |
| T2 偏好与策略优化 | 导师对多种回复评分，形成“为什么好/不好”的规则及数据集 | P1 | 优先修决策链，不以模板化覆盖自然语言 |
| T3 模型微调（可选） | 只有模型 API/权利/数据/验证门槛满足时进行监督或偏好微调 | 后期 | 不保证 DeepSeek 当前提供任意模型权重微调；不可假设支持 |

## 2. 数据来源与准入门槛

| 来源类型 | 可否直接入训练 | 准入要求 |
| --- | --- | --- |
| 纯虚构角色/自编多轮场景 | 可以优先建立示例与测试 | 明确“虚构”，审校安全性及覆盖范围 |
| 内部导师自行编写的示范对话 | 可在取得明确使用许可后纳入 | 标清作者、许可范围、版本与修改权 |
| 公开出版/网页/课程对话 | **不能自动复制** | 查明版权、授权和许可范围；仅可在允许的范围使用 |
| 导师与真实客户的咨询记录 | 默认不可收集/训练 | 必须另行评估合法依据、明确知情同意和敏感数据治理；仅去标识化不足以自动取得许可 |
| 解忧小屋的普通匿名聊天 | **默认不进入训练库** | 用户自主的特定、明确授权后才评估；不得后台静默采集 |
| 产品测试中的反馈 | 可先保存问题分类与人工填写的非敏感摘要 | 默认不复制完整私密对话，也不把截图直接公开 |

**强制分开**：会话中的当前 Issue 记忆（服务当次对话）与 C04 可重复使用的训练样本（跨用户存储）具有不同目的、授权和生命周期；不可共用一个隐式“自动保存”开关。

## 3. 处理流水线（离线）

~~~mermaid
flowchart LR
  S["许可来源<br/>虚构/导师授权/合规公开"] --> C["治理与清洗<br/>许可核验/敏感字段删除/人工复核"]
  C --> L["结构化标注<br/>JTBD/Issue/导师动作/质量"]
  L --> P["数据分组<br/>训练示例 / 偏好对 / 独立评测"]
  P --> E["离线回归与盲评<br/>对比质量/安全/自然度"]
  E --> A{"质量门禁达标？"}
  A -- "否" --> R["归因与修订候选"]
  R --> L
  A -- "是" --> V["人工批准版本<br/>Prompt/策略/可选微调"]
  V --> U["Staging 小规模验证<br/>必要时回滚"]
~~~

数据处理不应将原始敏感对话上传到公开 GitHub。GitHub 只保存数据结构定义、可公开的虚构案例、聚合指标及**脱敏**的示例；经许可的非公开数据必须存在权限受控的独立位置。

## 4. 建议的标注结构（数据字典，非现有 API）

| 字段 | 用途 |
| --- | --- |
| case_id / source_type / license_scope / consent_status | 唯一案例、来源、授权与可用范围 |
| scenario_domain | 工作、关系、家庭、成长等场景，不作为诊断标签 |
| turn_index / issue_id_pseudonym | 多轮结构与隔离信息 |
| current_job / help_progress / latest_user_preference | JTBD、观察到的进展、当前意愿 |
| dialogue_act_expected / method_id | 预定对话动作与镜像方法 |
| evidence_refs | 允许保留的脱敏事实/轮次证据 |
| response_candidate / rating / error_code | 候选回复、盲评评分与错误分类 |
| reviewer / reviewed_at / dataset_version | 人审及版本追踪 |
| split / leakage_group | 训练/验证/测试切分和防止同一话题泄漏 |

敏感标注限制：不将“心理疾病/依恋类型/人格问题”当作模型自行推断的真实标签；测评与医疗事实需更高等级治理。

## 5. 质量评分维度（建议 1–5 分＋硬门禁）

| 维度 | 要回答的问题 |
| --- | --- |
| 角色与边界 | 是否像同一名成熟 AI 导师，且不冒充真人/临床人员 |
| JTBD 跟随 | 是否跟随用户最新意愿与当前实际任务 |
| 镜像准确 | 是否基于已确认事实，且无未经证实的心理归因 |
| 开放提问 | 是否真实推进自主觉察，不是伪开放、二选一或重复追问 |
| 自然程度 | 是否像真实交流，有语言变化和合适节奏 |
| 用户自主 | 是否替用户给答案、任务或决定 |
| 安全与专业 | 是否漏掉高风险、误判日常行为或非法越过专业边界 |
| 有用进展 | 用户是否表达自己更清楚了，而不是 AI 自行宣布“解决” |

**硬门禁**：重要安全/专业边界违规、明确拒问被忽略、明确要求发问却完全不问、未经授权使用敏感数据，均不得用总体高分抵消。

## 6. 评审与训练隔离

- 评测集不参与任何训练或提示词逐条优化；存在相似多轮对话时整组隔离，防止背题。
- 可以记录人审意见和“为什么这个问题更好”，但不能把导师的单句话变成全局固定回复。
- 新版必须同时通过原有自动化、安全回归、未见过场景的盲评和小规模 Staging 实际多轮测试。
- 严禁“一个案例失败 → 加一个关键词禁用 → CI 全绿就上线”；必须定位到任务判定、方法选择、自然语言或输出校验模块。
- 数据集、规则集、Prompt 和运行版本使用独立版本号；变更记录链接 GitHub 设计 PR 和发布记录。

## 7. 首批可执行的低成本里程碑（未来，不在本 PR 实现）

1. 由 2–3 位内部导师共同编写 30 组**纯虚构**多轮场景，覆盖拒问/改口/新 Issue/催促给方案/明确求提问/安全专业边界。
2. 每组至少 3–6 轮，标注用户 JTBD、本轮允许动作、明显负例和用户是否获得实质进展。
3. 人工审查标签一致性；争议样本保留裁决记录而非多数投票硬改原典。
4. 建立一套独立保留评测集；先评估目前正式版和候选版的真实回复，不急着模型微调。
5. 针对有统计证据的失败类型提出一个最小架构修复 PR，检验跨场景改进与回归。
6. 达到使用许可、安全和质量门槛后，才评估是否需要 T2/T3 的更复杂训练。

## 8. 成功指标与目前状态

初期关注：高价值开放提问比例、明确用户意愿跟随率、错误归因/直接建议率、跨 Issue 污染、重复话术率、硬安全问题数、导师“有帮助”反馈。不能用“聊天时长”或“Token 越多”替代产品价值。

**当前全为 DESIGN_ONLY**：没有真实训练数据导入、没有改变 DeepSeek 权重、没有建立自动学习管线，也没有导入用户数据。
