## 六层主架构与一个横向数据闭环

| 层 | 模块 | 核心职责 | 是否用户每轮调用 |
| --- | --- | --- | --- |
| L1 | 产品目标与 JTBD | 当前任务、希望取得的进展、已发生的进展 | 概念与动态判断 |
| L2 | AI 导师身份 A02 | 角色一致性、边界、沟通气质 | 以规则约束，不单独模型调用 |
| L3 | 镜像技术原典 A03 | 原典保护、方法选择、空静爱、十原则 | 可按需选择；不强制逐个执行 |
| L4 | 对话运行内核 | 安全/专业 → Issue → 任务/进展 → 本轮导师动作 | 是 |
| L5 | 真人式表达 | 根据预定动作自然说话、提问、承认纠正；多气泡是 UI 展示 | 是 |
| L6 | 质量与治理 | 输出校验、Fallback、安全回归、灰度、脱敏诊断 | 是（必要校验） |
| C04 | **数据训练与评测闭环（离线）** | 授权数据治理、标注、回归、示例/偏好学习、试验、评测、版本控制 | **不是每轮聊天调用** |

## C04 与其他模块的边界

- C04 **不能读取当前普通会话并自动“训练模型”**。匿名聊天的临时上下文与持久语料采集严格隔离。
- C04 的主要产物：**黄金多轮案例、错误分型、对话策略对照、脱敏高质量示范、评审结果、可追溯模型/Prompt/规则实验版本**。
- C04 可以支持：基于示例的 Prompt 校准、监督/偏好数据集建设、离线质量评测；**参数微调只有在模型/服务商支持且数据有合规授权时才考虑**。
- 导师身份与镜像原典属于稳定约束，不能被统计反馈或模型训练自动改写。
- 安全/隐私边界属于发布硬门禁，训练效果不能将其降级。
- 原则上**不增加每轮调用次数**，以离线分析和迭代为主。

## 组合方式：每轮只决定必要内容

示例：用户说“你倒是问啊”时，运行内核应该输出 ASK_OPEN_QUESTION；表达引擎根据用户先前真正说过的事实组织语言；校验必须看见有效开放问题。数据模块随后可以用这类已许可/虚构案例来评测新版是否再次犯错，但**不能把单条例句做成固定回复模板**。

## 设计阶段计划

1. **D3-A（当前）**：新增 C04 数据模块架构与训练数据治理规则；文档归档。

3. D3-C：内部导师用虚构案例盲评 AI 回复，优先识别根因（JTBD/策略/方法/表达/校验），再做离线 Prompt 与规则 A/B。
4. D3-D：评审通过才单独授权合适的上线流程；上线后统计匿名汇总反馈，不默认收集完整敏感内容。
5. 原 A03 方法卡继续后移，先不继续 MM-03 量化规则卡的细化。

## 两条执行约束

- **设计版本 ≠ 软件发布版本**：V3.1 仅是架构命名，现有网页尚未实现此架构。
- **内测 ≠ 公共训练授权**：产品上架、导师试用或用户愿意聊天，都不自动意味着许可复制对话用于数据集训练。
