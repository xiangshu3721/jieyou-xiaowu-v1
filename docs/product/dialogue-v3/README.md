## 为什么建立本目录

保留 JTBD 的「用户当前任务 → 用户进展 → 本轮导师动作 → 用户反馈」主线，将 AI 导师身份、镜像原典、方法适配、真人式语言和可追溯技术实现解耦。目标不是增加 Agent，而是减少相互矛盾的规则、无效回复和逐句补丁。

## 架构六层（设计，不是固定聊天顺序）

1. 产品使命与 JTBD：用户为何而来、希望得到什么进展。
2. AI 导师身份：是谁、稳定的人格气质、角色与专业边界。
3. 镜像方法论：原典只读；产品方法可版本化。
4. JTBD 对话决策：安全 / Issue / 任务 / 进展 / 对话动作。
5. 真人式自然表达：以既定动作生成自然中文对话。
6. 质量治理：输出校验、无效回复降级、脱敏轨迹、跨轮回归和发布闸门。

## 已确认的最新产品要求（与旧版区分）

- 普通解忧对话全程不直接替用户给答案、步骤、方案和练习；以倾听、镜像、开放提问、用户自主觉察为核心。
- **开放式提问是探索能力的核心，但不是每轮强制共情 + 提问。** 用户明确邀请提问时应真实提一个与上下文相关的开放问题。
- 用户最新的明确意愿优先于旧的普通交流偏好；用户拒绝提问、暂停、结束应被尊重。
- 安全危机所需现实支持、专业转介和用户明确要求的真人预约是独立优先边界。
- 原典不可因产品行为合同而修改；如原典允许、产品不采用，必须记录差异。
- 对外如实表明 AI 身份，不宣称具备真人情感、临床资质或绝对保密能力。

以上为此前交互确认的产品方向；**本目录的新增细节仍需产品复核，未自动升格为已实施规则**。

## 保存与交接约定

- 每完成一个独立设计阶段，先更新对应 Markdown + 本目录 CHANGELOG，再生成独立文档 PR，附 commit SHA、基线、变更、待审核决策、明确未验证项；未经授权不直接合并或部署。
- 不通过修改旧文档来伪造当时已确认的事实；新规则保留历史记录与来源。
- 原典变更仅接受新的原始版本登记；解读与适配变更不覆盖原典。
- 全量代码重构、正式上线、真实模型付费评测、飞书写入需要单独授权。
