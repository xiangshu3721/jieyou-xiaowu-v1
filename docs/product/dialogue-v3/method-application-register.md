# A03｜方法应用规则与冲突登记册 v0.1

> 规则登记册用于把不可改动的原典，与可复核、可迭代的产品应用分离。它本身不是新的 Prompt。所有条目为设计候选，待产品批准后才进入代码合同。

## 1. 规则优先级（候选）

1. **安全与合法专业边界**：迫近危险时提供必要的现实支持；药物和其他专业事务不得假装诊断。
2. **当前明确的用户边界与授权**：拒问、结束、暂停、真人意愿等；明确改口以最近有效意愿为准。
3. **产品行为合同**：普通对话全程不直接给解决方案、步骤和练习；通过镜像与开放探索支持自主决定。
4. **AI 导师身份宪章**：诚实、稳重、不投射、不说教、不操纵。
5. **镜像方法适配**：根据 JTBD、当前证据、对话动作选择合适的方法；非固定顺序。
6. **语言与交互偏好**：自然口语、长短变化和气泡节奏；不能推翻前述高优先级规则。

## 3. 已识别的来源差异 / 冲突

| 冲突 ID | 原典或历史规则 | 当前产品应用决定 | 不得如何处理 |
| --- | --- | --- | --- |
| CONFLICT-01 | 《导师十原则》p3 特定情况下允许导师分享参考经验 | 当前解忧小屋普通对话仍不直接给方案和答案 | 不能删除或改写原典允许的例外 |
| CONFLICT-02 | 《镜像技术》含卡牌及现场观察身体行为 | 匿名文字 H5 不默认使用实体卡牌，不声称观察到看不见的行为 | 不得冒充真实现场观察 |
| CONFLICT-03 | 原典破冰含口头“仅对方知道”的绝对保密示例 | 采用符合真实数据处理与同意机制的隐私说明 | 不得照搬无法保证的承诺 |
| CONFLICT-04 | 历史 V1.9 允许轻量帮助 / 若明说要方法可扩展 | 最新用户对普通解忧交流要求全程非指令式 | 不让旧 Prompt 或旧自动测试覆盖最新合同 |
| CONFLICT-05 | 用户希望开放式提问为核心 | 同时反对每轮机械“共情+提问” | 不能把开放式问题设成每轮无条件强制 |
| CONFLICT-06 | 镜像原典可能涉及深入根源探索 | V1.9 AI 默认限 D0–D2，D3 不自动执行 | 不借高深问题进行未经授权的深度治疗 |

## 4. 方法选择的合同（设计）

输入：当前 Issue 的用户确认事实、最新用户意愿、JTBD 任务与已确认进展、本轮 DialogueAct、安全/专业边界、已问问题的去重记录。

输出（概念字段，不是已存在 API）：
- method_id：来自 mirror-method-mapping.md。
- policy_rule_id：本登记册规则码。
- focus：要探索的一个主题/缺口。
- evidence_ref：脱敏的来源轮次/事实 ID，而非原始敏感全文。
- constraints：不预设、不直接给方案、不得重复已答问题、当前拒问等。
- rationale_code：做此选择的可追踪原因。

若上下文不足或方法不适合，允许 **NO_METHOD / LISTEN / RESPECT_BOUNDARY**，不强行调用某一种技术。

## 5. 变更流程

- 原典内容变动 → 登记新的权威原件与版本，**不覆盖旧原典**。
- 应用方式变动 → 改动 APP 条目 + CONFLICT 记录 + 对应的多轮测试 + 设计版本。
- 重要产品边界变动 → 需明确人工确认，再进入代码和发布。
- 测试证据必须区分规则/Handler Mock、实际模型效果、Staging、Production；不能以 Mock PASS 冒称真实体验 PASS。
