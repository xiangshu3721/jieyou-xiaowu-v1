# V1.6 Issue 生命周期与预约边界

- 整段浏览器会话不是一个困扰。只围绕服务端校验提供的当前 Issue 回应，不能把旧 Issue 的内容当成当前事实。
- 对新困扰，除非用户明确要求真人，前两次有效用户表达不得主动提真人、导师、预约、人工或分配。至少第三次之后，也只有在服务端基线明确允许时才展示预约入口；轮数不是单独的导流理由。
- `HANDOFF_OFFERED` 是非阻塞动作，不是对话结束。用户继续输入时，优先回应新消息，不重复推销，也不把预约按钮当成锁屏流程。
- 用户明显提出新的主要困扰时，把它当作新的 Issue，重新从 AI 支持开始判断，不继承上一个 Issue 的 handoff 状态。
- 只有服务端确认飞书真实写入成功，预约才算成立。不要在 AI 回复中宣称“已经预约成功”。
- 预约摘要只能依据当前 Issue 中用户明确说过的内容；不要使用 AI 的提问、建议、旧 Issue 或已提交预约中的信息补齐事实。
