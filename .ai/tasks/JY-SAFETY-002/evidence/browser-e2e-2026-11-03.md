# 本地浏览器证据

时间：2026-11-03（Asia/Shanghai）

页面：`http://127.0.0.1:5175/chat`，本地 Vite 页面；未使用 Production 页面。

隔离范围：使用全新 ChatGPT in-app browser context 创建的本地标签；初始页面只有欢迎语，没有历史用户消息。测试内容均为虚构字符串 `JY-SAFETY-002 ...`。

## 已观察结果

1. 在全新隔离标签发送 `JY-SAFETY-002 虚构消息 A`。发送期间页面显示 `正在听…`，清空按钮为 disabled；发送完成后显示用户消息和本地代理失败提示 `请求失败，请稍后重试`。
2. 清空按钮打开原生确认框，原文为：
   `确定清空这一次对话吗？这将删除当前浏览器的本地聊天、相关问题状态和本地预约快照，且无法恢复；不影响已经提交的正式预约记录。`
3. 选择 `Cancel`，确认框关闭；之后页面仍显示 `JY-SAFETY-002 虚构消息 A` 及错误提示，证明取消不会清空当前页面消息。
4. 在同一隔离上下文重新打开新标签，页面只显示欢迎语，没有 A，证明 `OK` 已清除这条虚构消息；该标签没有其他历史记录。
5. 刷新清空后的页面，仍为空白聊天状态；随后发送 `JY-SAFETY-002 刷新后新消息 B`，页面显示 B，随后显示本地代理失败提示，证明清空后刷新及新消息流程可用。
6. 先前记录 `我想清空聊天记录` 也曾在本地浏览器中进入普通聊天流程，没有触发清空。

## Session / Issue 记录

- Session：`jieyou-main-session`。该值由现有存储实现固定，不因清空改变；清空操作写入新的 Session 对象。
- 清空前 Issue：旧 opaque UUID，浏览器可见层不展示原始值。
- 清空后 Issue：新 opaque UUID；`clearLocalMessages()` 使用 `newIssue(now)` 重建，浏览器可见层不展示原始值。
- 可直接观察到的脱敏结果：清空前消息包含 A；OK 后及刷新后消息为空；新消息 B 可正常写入并显示。
- 限制：当前 CUA 接口没有页面 JavaScript/IndexedDB 读取能力，因此没有伪造具体 UUID，也没有声称从 IndexedDB 直接读出了这些 ID。代码核对位置为 `src/client/storage.ts:34-42,237-243`，页面行为核对如上。

## 未验证项

- 未在浏览器中验证学习授权按钮的云端成功态；隔离 Staging 的 `learningConfigured=false`，该部分由本地 Mock 测试和 Staging 503 失败响应覆盖。

结论：AT001 与 AT002 的页面行为验收通过；精确 Issue UUID 的直接 IndexedDB 读回受当前浏览器工具能力限制，已明确记录，不补造值。
